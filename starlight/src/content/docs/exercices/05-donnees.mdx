## Partie 2 : Premiers pas en programmation orientée objet

Jusqu'ici, les données vivaient dans des tableaux et le comportement dans des fonctions. 
La programmation orientée objet réunit les deux : 

1. une **classe** est un modèle qui décrit des **attributs** (les données) et des **méthodes** (le comportement) ; 
2. un **objet** est une instance concrète créée à partir de ce modèle avec `new`.

<MarginNote type="rappel" titre="Vous en utilisez déjà">
`PDO` vu cette semaine pour la connexion à la base de données, est une classe.  
`new PDO(...)` crée un objet, et `$pdo->query(...)` appelle une de ses méthodes.
</MarginNote>

Une classe en PHP réunit quatre éléments : le mot-clé `class`, des attributs, un constructeur et des méthodes.

```php
<?php
class CompteBancaire                 // 1. le mot-clé class et un nom
{
    private float $solde;            // 2. un attribut (donnée), ici privé

    public function __construct(float $depart)   // 3. le constructeur
    {
        $this->solde = $depart;      //    $this désigne l'objet courant
    }

    public function deposer(float $montant): void  // 4. une méthode (comportement)
    {
        $this->solde += $montant;
    }

    public function solde(): float
    {
        return $this->solde;
    }
}

$compte = new CompteBancaire(100);   // créer un objet avec new
$compte->deposer(50);                // appeler une méthode avec ->
echo $compte->solde();               // 150
```

La visibilité `public` ou `private` contrôle l'accès : un attribut `private` ne se manipule que par les méthodes de la classe. On parle d'**encapsulation** : l'objet protège ses données et n'expose que ce qu'il choisit.

### Exercice 12 &ndash; Enregistrer une réservation

**Base de données**

Écrivez une fonction qui insère une réservation. Si la place vient d'être prise par quelqu'un d'autre, la contrainte `UNIQUE` bloque l'insertion : la fonction retourne alors `false`.

Signature : `reserverPlace(PDO $pdo, string $representation, string $place, string $nom, string $courriel): bool`

<Checkpoint question="Indice">
Un `INSERT` préparé range chaque valeur dans un paramètre nommé, jamais par concaténation. Enveloppez l'exécution dans un `try/catch` : une violation de la contrainte `UNIQUE` lève une `PDOException`, que vous interceptez pour retourner `false`.
</Checkpoint>

<Checkpoint question="Solution">

```php
<?php
function reserverPlace(PDO $pdo, string $representation, string $place, string $nom, string $courriel): bool
{
    try {
        $requete = $pdo->prepare(
            'INSERT INTO reservations (representation, place, nom, courriel)
             VALUES (:rep, :place, :nom, :courriel)'
        );
        $requete->execute([
            'rep'      => $representation,
            'place'    => $place,
            'nom'      => $nom,
            'courriel' => $courriel,
        ]);
        return true;
    } catch (PDOException $e) {
        // La place était déjà réservée (contrainte UNIQUE).
        return false;
    }
}
```

</Checkpoint>
