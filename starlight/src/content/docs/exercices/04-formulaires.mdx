## Exercice 2 — Filtrer un catalogue

**Dossier de départ** : `ex02-catalogue/`

L'objectif ici est d'ajouter au catalogue un formulaire de filtres en mode `GET` 
pour prendre en compte les filtres suivants: catégorie, prix maximal, disponibilité.

#### À faire

<Steps>

1. Lire les trois filtres dans `$_GET`.

2. Valider chaque filtre avant de s'en servir. Une catégorie absente de `data/categories.php` et un prix qui n'est pas un nombre positif se ramènent à « pas de filtre » plutôt qu'à une erreur.

3. Réduire la liste affichée en appliquant les filtres retenus.

4. Écrire le formulaire, avec `method="get"`, traité par la même page, avec un bouton de réinitialisation.

</Steps>

#### Critères de réussite

- Les trois filtres se combinent : choisir une catégorie **et** un prix maximal réduit deux fois la liste.
- Après envoi, le formulaire réaffiche les valeurs actives — le menu reste sur la catégorie choisie, la case reste cochée.
- L'adresse obtenue, recopiée dans un autre onglet, produit exactement le même résultat.
- Modifier l'adresse à la main pour y mettre `categorie=nimportequoi` affiche le catalogue complet, sans avertissement PHP.
- Le nombre de produits affiché correspond à la liste réellement présentée.

<Aside type="syntaxe" title="Réafficher l'état d'un champ">
Pour un menu déroulant, l'option retenue porte l'attribut `selected` ; 
pour une case, l'attribut `checked`.  
Les deux s'écrivent conditionnellement : `<?php echo $cle === $categorie ? "selected" : ""; ?>`.
</Aside>

{/* <Aside type="exemple" title="Bonne pratique — la liste blanche">
Comparer la valeur reçue à une liste de valeurs admises, comme le fait `data/categories.php`, est plus sûr que de tenter de repérer ce qui serait dangereux. La liste des valeurs acceptables est connue et courte ; la liste des valeurs problématiques ne l'est pas.

## Exercice 3 — Une barre de recherche

**Dossier de départ** : `ex03-recherche/`
> ✅ Les filtres de l'exercice 2 sont déjà écrits dans le code fourni.

L'objectif ici est d'ajouter un champ de recherche qui filtre les produits par nom, 
sans perdre les filtres déjà actifs.

#### À faire

<Steps>

1. Lire le terme (tappé dans la barre de recherche) dans `$_GET["q"]` et le normaliser.

2. Filtrer les produits pour ne garder que ceux dont le nom contient ce terme, sans tenir compte de la casse ni des espaces avant ou après le terme.

3. Prévoir un message lorsque la recherche ne donne rien, plutôt qu'une grille vide.

4. Intégrer le champ au formulaire existant, de façon qu'une recherche conserve la catégorie et le prix maximal déjà choisis.

</Steps>

#### Critères de réussite

- Chercher `érable` avec la catégorie « Confiseries » selectionnée donne uniquement les confiseries dont le nom contient « érable ».
- Chercher `SIROP` donne le même résultat que `sirop`.
- Une recherche sans résultat affiche un message et propose de réinitialiser.
- Vider le champ de recherche et renvoyer le formulaire rétablit la liste filtrée, sans perdre les autres filtres.

<MarginNote type="astuce">
Un champ de recherche et des filtres dans le même formulaire partent ensemble à chaque envoi : 
c'est le moyen le plus simple de ne rien perdre. Si vous les séparez en deux formulaires, il faudra 
rejouer les filtres en champs cachés dans celui de la recherche.
</MarginNote>
