## Entrainement

Le site **Nord & Tasse** est une petite boutique montréalaise spécialisée dans le café et les accessoires pour la préparation du café à la maison.

<Aside type="note" title="Pour commencer">
Pour ces exercices, crée un dossier `site-nord-tasse` dans le dossier `xampp/htdocs`
et n'oublie pas de démarrer (*Start*) XAMPP.
</Aside>

### Exercice 1 : Optimiser la structure

Le site contient actuellement trois pages :

* une page d'accueil ;
* une page qui présente les produits ;
* une page de contact.

Repère ce qui est **identique** ou commun aux trois pages et qui pourrait être extrait dans des fragments réutilisables. Identifie également ce qui est **propre** à chaque page.

Crée ensuite les fragments nécessaires et intègre-les dans chacune des pages avec `include` ou `require`.

<Checkpoint question="Indice 1">

Compare les trois pages côte à côte.

Certaines parties sont répétées **exactement** dans les trois fichiers. Par exemple, la navigation et le pied de page sont identiques.

Plutôt que de les copier dans chaque page, elles pourraient être placées dans des fichiers séparés et incluses avec `include`.

</Checkpoint>

<Checkpoint question="Indice 2">

Le début du document est presque identique dans les trois pages, mais le contenu de `<title>` change :

```html
<title>Accueil — Nord & Tasse</title>
```

```html
<title>Produits — Nord & Tasse</title>
```

```html
<title>Contact — Nord & Tasse</title>
```

Il n'est pas nécessaire de créer trois fragments différents.

Un fichier inclus **a accès aux variables définies avant son `include`**.

Il est donc possible de définir une variable `$titre` dans chaque page avant d'inclure le fragment commun.

Par exemple :

```php
<?php
$titre = 'Accueil';
?>
```

</Checkpoint>

<Checkpoint question="Indice 3">

Une organisation possible du projet pourrait commencer ainsi :

```text
/
├── accueil.php
├── produits.php
├── contact.php
└── fragments/
    ├── ...
    ├── ...
    └── ...
```

Demande-toi quelles parties appartiennent à la **structure générale du site** et lesquelles représentent réellement le **contenu propre à chaque page**.

</Checkpoint>

### Exercice 2 : Optimiser la navigation

Dans l'exercice précédent, la navigation a été déplacée dans un fragment commun.

Cependant, la liste des liens est encore directement écrite dans ce fragment. Plus le site grandit, plus cette façon de faire devient difficile à maintenir.

Modifie le site afin que sa navigation soit construite à partir d'un **fichier de configuration** décrivant les pages disponibles.

La configuration doit permettre de définir au minimum :

* l'identifiant d'une page ;
* son titre ;
* son URL.

La navigation doit ensuite être générée à partir de cette configuration plutôt que d'une liste de liens écrite manuellement.

Pour aider le visiteur à se repérer dans le site, le lien correspondant à la **page courante** doit également se distinguer visuellement des autres.

Ajoute aussi l'attribut HTML approprié pour indiquer sémantiquement qu'un lien représente la page actuellement affichée.

<Checkpoint question="Indice 1">

Une structure de données peut représenter les différentes pages du site.

Pour chaque page, il faut conserver les informations nécessaires pour produire un lien de navigation.

</Checkpoint>

<Checkpoint question="Indice 2">

Pour distinguer la page courante, le fragment doit savoir **quelle page est actuellement affichée**.

Une possibilité consiste à définir une variable propre à chaque page avant d'inclure les fragments communs.

</Checkpoint>

<Checkpoint question="Indice 3">

Lorsque la page générée correspond à la page courante, ajoute :

* une classe CSS permettant de la distinguer visuellement ;
* l'attribut `aria-current="page"`.

Par exemple, le HTML final pourrait contenir :

```html
<a href="produits.php" class="active" aria-current="page">
  Produits
</a>
```

</Checkpoint>

### Exercice 3 : Optimiser les données des produits

La page `produits.php` contient actuellement à la fois :

* les données des produits ;
* le HTML utilisé pour les présenter.

Cette organisation fonctionne avec quelques produits, mais elle devient rapidement difficile à maintenir lorsque le catalogue grandit.

Modifie la page afin de **séparer les données de leur affichage**.

Les informations sur les produits doivent être déplacées dans un fichier distinct. La page `produits.php` doit ensuite utiliser ces données pour générer la liste des produits.

La présentation HTML d'un produit doit également être extraite dans un **template réutilisable**.

#### Résultat attendu

Une fois le travail terminé :

* les informations sur les produits ne sont plus directement écrites dans `produits.php` ;
* les produits sont définis dans un fichier distinct ;
* `produits.php` parcourt les données disponibles pour afficher le catalogue ;
* la structure HTML utilisée pour présenter un produit n'est définie qu'une seule fois ;
* tous les produits utilisent le même template de présentation ;
* l'ajout d'un produit ne nécessite pas de recopier un bloc HTML complet.

<Checkpoint question="Indice 1">

Les produits ont tous une structure semblable : un nom, une description, un prix et parfois un format.

Une collection de tableaux associatifs permet de représenter ce type de données en PHP.

</Checkpoint>

<Checkpoint question="Indice 2">

Le template d'un produit pourrait recevoir, par l'intermédiaire d'une variable, les informations du produit actuellement traité.

Il devrait être responsable uniquement de sa présentation, par exemple :

```html
<section>
  <h2>...</h2>
  <p>...</p>
  <p>...</p>
</section>
```

Les valeurs affichées doivent toutefois provenir des données du produit et non être écrites directement dans le template.

</Checkpoint>

<Checkpoint question="Indice 3">

La structure du projet pourrait maintenant contenir des fichiers dédiés aux données et aux templates :

```text
/
├── accueil.php
├── produits.php
├── contact.php
├── config.php
├── donnees/
│   └── ...
└── fragments/
    ├── entete.php
    ├── navigation.php
    ├── ...
    └── pied.php
```

</Checkpoint>


## Synthèse &ndash; Site personnel

Tu dois maintenant créer un petit **site personnel de type portfolio** permettant de te présenter, de montrer quelques réalisations et de résumer ton parcours.

### Pages obligatoires

Ton site doit contenir **au moins trois pages**.

#### Accueil

La page d'accueil présente rapidement la personne et permet au visiteur de comprendre qui elle est et ce qu'elle recherche.

Elle doit notamment présenter :

* une courte présentation ;
* quelques intérêts ;
* les principales compétences ;
* les disponibilités ou le type d'opportunités recherchées ;
* une façon de prendre contact.

Tu peux organiser cette information comme tu le souhaites.


#### Réalisations

La page `realisations.php` constitue le portfolio.

Elle présente plusieurs projets ou réalisations de façon suffisamment détaillée pour permettre au visiteur de comprendre le travail effectué.

Chaque réalisation devrait contenir plusieurs informations pertinentes, par exemple :

* le titre du projet ;
* une description ;
* les technologies utilisées ;
* le contexte du projet ;
* le rôle ou les responsabilités ;
* un lien vers le projet ou son dépôt, lorsque pertinent.

Les réalisations doivent être présentées de manière cohérente et utiliser une structure visuelle commune.

#### À propos

La page `a-propos.php` présente plus en détail le parcours de la personne.

Elle doit notamment contenir :

* la formation ;
* les expériences professionnelles ou scolaires ;
* d'autres informations pertinentes au profil présenté.

Tu peux y ajouter d'autres sections selon le contexte choisi : certifications, langues, activités, implication, intérêts professionnels, etc.

### Contenu minimal

Le portfolio doit contenir au minimum :

* **3 pages** ;
* **3 réalisations distinctes** ;
* plusieurs compétences ;
* au moins une formation ;
* au moins une expérience ;
* des informations permettant de contacter la personne.

Tu peux ajouter d'autres pages ou sections si elles apportent quelque chose au portfolio.


### Structure

L'organisation des fichiers est laissée à ton jugement.

Elle doit toutefois montrer clairement la séparation entre :

* les pages du site ;
* les éléments réutilisables ;
* la configuration ;
* les données utilisées pour générer certains contenus.

Choisis des noms de fichiers et de dossiers qui permettent de comprendre facilement leur rôle.

### Présentation

Ajoute une ou plusieurs feuille de style CSS afin de donner au portfolio une présentation simple mais soignée.
Le site doit notamment être lisible, facile à parcourir et utilisable sur différentes tailles d'écran.

L'objectif n'est pas de produire une interface complexe, mais de présenter correctement le contenu et de montrer une bonne organisation du site.
