Cette page rassemble des questions sur l'ensemble du cours, de la construction d'une page dynamique jusqu'à la conception d'une API. Elles sont regroupées en six thèmes, qui suivent l'ordre du cours.

Trois formes de questions alternent :

- des **choix multiples**, pour vérifier une notion ;
- de la **lecture de code** : un extrait, puis ce qu'il produit ou ce qu'il faut y changer ;
- des **réponses courtes**, qui demandent d'expliquer un « pourquoi ». La réponse proposée se déplie, une fois la vôtre formulée.

<Aside type="astuce" title="Comment s'en servir">
Une réponse trouvée par élimination ne garantit pas que la notion soit comprise. Pour les réponses courtes en particulier, formulez la vôtre avant d'ouvrir le corrigé, puis comparez le raisonnement plutôt que les mots. Chaque explication indique la page où revoir la notion.
</Aside>

```php
<?php
$id = $_GET['id'];
$produit = $pdo->query("SELECT * FROM produits WHERE id = $id")->fetch();
```

<Checkpoint question="Ce code fonctionne avec l'adresse produits.php?id=7. Quel risque présente-t-il, et comment le corriger ?">
La valeur reçue est insérée telle quelle dans la requête SQL : une adresse construite avec un fragment de SQL à la place du nombre modifierait la requête elle-même. C'est une injection SQL. La correction consiste à utiliser une requête préparée, `prepare('... WHERE id = :id')` puis `execute(['id' => $id])`, qui transporte la valeur à part du texte de la requête. Valider que l'identifiant est un entier ajoute une précaution, sans remplacer la requête préparée. À revoir : « Préserver les données », requêtes préparées.
</Checkpoint>

```php
<?php
class Produit
{
    private float $prix;

    public function __construct(float $prix)
    {
        $this->prix = $prix;
    }
}

class ProduitPerissable extends Produit
{
    public function prixSolde(): float
    {
        return $this->prix * 0.8;
    }
}
```

<Checkpoint question="La méthode prixSolde() ne rend pas le prix attendu. Pourquoi, et quelles sont deux façons de corriger ?">
Un attribut `private` de la classe parente n'est pas accessible depuis la classe enfant, même si celle-ci en hérite : `$this->prix` ne désigne pas, dans `ProduitPerissable`, l'attribut de `Produit`. On peut déclarer l'attribut `protected`, ce qui le garde caché de l'extérieur mais le rend visible des sous-classes, ou passer par un accesseur public, `getPrix()`, défini dans `Produit`. À revoir : « Des objets qui collaborent », l'héritage.
</Checkpoint>
