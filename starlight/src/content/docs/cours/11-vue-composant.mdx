Dans la page précédente, nous avons rendu un portfolio HTML interactif avec Vue, chargé depuis un CDN. Nous avons aussi découvert la structure d'un composant `.vue`.

Nous allons maintenant créer une **application Vue avec Vite**, répartir son interface en composants et leur faire échanger des informations. Nous utiliserons d'abord des **données locales** pour nous concentrer sur la conception, puis nous les remplacerons par des données chargées avec `fetch`.

## D'une page à une application

Notre application présentera un répertoire de cafés étudiants, avec des cartes, des favoris et des filtres rapides. Nous prendrons comme référence le domaine de **Café sans-fil**, un projet qui répertorie les cafés étudiants de l'Université de Montréal.

Plutôt que de réunir toute l'interface dans un seul fichier, nous répartirons les responsabilités à travers plusieurs composants (chacun dans un fichier) :

```text
App.vue                    État commun : cafés, favoris et filtres
│                          Chargement des données et composition de la page
│
└── CarteCafe.vue          Affichage d'un café et de son bouton favori
                           Réutilisé pour chaque élément de la liste
```

#### Trois principes guideront nos choix

1. **Un composant doit avoir une seule responsabilité.** `CarteCafe` affiche un café ; il ne décide ni de la provenance des données, ni des filtres à appliquer.
2. **L'état est placé là où il doit être partagé.** Les favoris concernent plusieurs cartes et le filtre « Mes favoris » : `App.vue` les conserve.
3. **Les données descendent, les événements remontent.** Le parent transmet des valeurs par des **props** ; l'enfant signale les actions par des **événements**.

<Highlight couleur="ambre">Un composant ne devrait pas avoir à connaître toute l'application pour remplir sa responsabilité. On définit les informations qu'il reçoit et les événements qu'il peut émettre.</Highlight>

</Aside>

### Créer `CarteCafe.vue`

Créer le fichier `src/components/CarteCafe.vue` :

```vue
<script setup>
import { computed } from 'vue'

const props = defineProps({
  cafe: { type: Object, required: true },
})

const NOMS_PAIEMENT = {
  CASH: 'Comptant',
  DEBIT: 'Débit',
  CREDIT: 'Crédit',
}

const paiements = computed(() =>
  (props.cafe.payment_details ?? [])
    .map((p) => NOMS_PAIEMENT[p.method] ?? p.method)
    .join(', ') || 'Non précisé',
)
</script>

<template>
  <article class="carte">
    <img
      v-if="cafe.banner_url"
      :src="cafe.banner_url"
      :alt="`Photo du café ${cafe.name}`"
      loading="lazy"
    />

    <div class="contenu">
      <header><h2>{{ cafe.name }}</h2></header>
      <p class="statut" :class="cafe.is_open ? 'ouvert' : 'ferme'">
        {{ cafe.is_open ? 'Ouvert' : 'Fermé' }}
        <span v-if="cafe.status_message"> · {{ cafe.status_message }}</span>
      </p>
      <p>{{ cafe.description || 'Aucune description disponible.' }}</p>
      <p class="infos">
        {{ cafe.location?.pavillon || 'Pavillon non précisé' }}
        <span v-if="cafe.location?.local">, {{ cafe.location.local }}</span>
        <br />Paiement : {{ paiements }}
      </p>
    </div>
  </article>
</template>

<style scoped>
.carte { background: #fff; border: 1px solid var(--bord); border-radius: 12px; overflow: hidden; }
img { width: 100%; height: 140px; object-fit: cover; }
.contenu { padding: 12px 14px; display: flex; flex-direction: column; gap: 6px; }
header { display: flex; justify-content: space-between; align-items: start; gap: 8px; }
h2, p { margin: 0; }
h2 { font-size: 1.1rem; }
.statut { font-size: .85rem; font-weight: 600; }
.ouvert { color: #067647; }
.ferme { color: #b42318; }
.infos { font-size: .85rem; color: var(--gris); }
</style>
```

##### Remarques:

- Dans le script, nous utilisons `props.cafe` ; 
- Dans le gabarit (`<template>`), `cafe` est directement accessible. 
- La propriété calculée `paiements` convertit les codes de paiement en libellés lisibles.
- L'expression `?? []` prévoit le cas où `payment_details` est absent ou vaut `null`. 
  > Lorsque les données proviennent d'une source externe, il faut éviter de supposer que tous les champs facultatifs seront toujours présents.

<MarginNote type="astuce" titre="Propriétés calculées">
La propriété `paiements` ne modifie pas le café : elle produit une valeur d'affichage à partir de ses données. Nous utilisions déjà `computed()` pour filtrer les projets du portfolio.
</MarginNote>

## Étape 3 : Faire communiquer les composants

Ajoutons un bouton permettant d'indiquer les cafés favoris. Le bouton se trouve dans `CarteCafe`, mais **la liste des favoris appartient à `App.vue`**, car elle concerne plusieurs cartes et servira aussi à filtrer la liste.

### Observer les événements émis (`defineEmits`)

<DemoEmits client:visible />

Un composant enfant peut déclarer et émettre un événement :

##### Composant enfant `BoutonFavori.vue`

```vue "defineEmits" "emit('basculer')"
<script setup>
defineProps({ actif: { type: Boolean, default: false } })
const emit = defineEmits(['basculer'])
</script>

<template>
  <button type="button" aria-label="Favori" :aria-pressed="actif" @click="emit('basculer')">
    {{ actif ? '★' : '☆' }}
  </button>
</template>
```

Le parent reçoit cet événement et décide comment modifier sa liste :

##### Composant parent

```vue "basculer" "@basculer"
<script setup>
import { ref } from 'vue'
import BoutonFavori from './BoutonFavori.vue'

const noms = ['Café Démo Agora', 'Café Démo Jardin']
const favoris = ref([])

function basculer(nom) {
  if (favoris.value.includes(nom)) {
    favoris.value = favoris.value.filter((f) => f !== nom)
  } else {
    favoris.value.push(nom)
  }
}
</script>

<template>
  <p v-for="nom in noms" :key="nom">
    {{ nom }}
    <BoutonFavori :actif="favoris.includes(nom)" @basculer="basculer(nom)" />
  </p>
</template>
```

<Aside type="definition" title="Événement émis (emit)">
Un composant enfant utilise `defineEmits()` pour déclarer les événements qu'il peut produire, puis `emit('nom', valeur)` pour en déclencher un. Le parent écoute ces événements avec `@nom`. L'enfant **signale une intention ou une interaction** ; il ne décide pas nécessairement de la modification des données du parent.
</Aside>

<Highlight couleur="ambre">Les données descendent par les props et les interactions remontent par les événements émis.</Highlight>

## Étape 4 : Charger les données depuis une API

Nous avons maintenant une interface qui fonctionne **sans connexion (réseau)**. 
Pour l'alimenter avec des données distantes, nous n'avons pas besoin de modifier `CarteCafe` : c'est `App.vue` qui remplacera sa collection de cafés.

### La source de données

L'API publique de *Café sans-fil* est présentée à l'adresse `https://api.cafesansfil.ca/docs`. Une requête envisagée pour la liste est :

```http
GET https://api.cafesansfil.ca/v1/cafes?size=100
```

Dans cette activité, nous travaillons avec le format de réponse suivant :

```json
{
  "items": [
    {
      "slug": "demo-agora",
      "name": "Café Démo Agora",
      "is_open": true,
      "location": { "pavillon": "Pavillon A", "local": "A-101" },
      "payment_details": [{ "method": "DEBIT" }]
    }
  ],
  "total": 1,
  "page": 1,
  "size": 1,
  "pages": 1
}
```

<Aside type="caution" title="Source locale fournie pour les exercices">
L'accès à une API externe peut être interrompu, ou une requête depuis le navigateur 
peut être bloquée par la politique CORS. Pour que l'activité reste réalisable, 
commencer par **`public/cafes.json`**, fourni avec le matériel de la page, 
qui reproduit ce format avec des **données fictives**. 

L'adresse `/cafes.json` fonctionne avec Vite parce que les fichiers de `public/` sont servis à la racine du site. 
Pour utiliser l'API distante, remplacer ensuite `SOURCE` par son adresse et vérifier au préalable la réponse et l'accès depuis le navigateur.
</Aside>

### Observer les états d'un chargement

<DemoChargement client:visible />

La démonstration simule une réponse réussie ou un échec réseau :

```vue
<script setup>
import { ref, onMounted } from 'vue'

const cafes = ref([])
const chargement = ref(true)
const erreur = ref('')
const simulerErreur = ref(false)

function fausseRequete() {
  return new Promise((resoudre, rejeter) => {
    setTimeout(() => {
      if (simulerErreur.value) rejeter(new Error('réseau indisponible'))
      else resoudre(['Café Démo Agora', 'Café Démo Jardin'])
    }, 1000)
  })
}

async function charger() {
  chargement.value = true
  erreur.value = ''
  try {
    cafes.value = await fausseRequete()
  } catch (e) {
    erreur.value = `Échec du chargement : ${e.message}`
  } finally {
    chargement.value = false
  }
}

onMounted(charger)
</script>

<template>
  <p v-if="chargement">Chargement…</p>
  <p v-else-if="erreur" role="alert">{{ erreur }}</p>
  <ul v-else>
    <li v-for="cafe in cafes" :key="cafe">{{ cafe }}</li>
  </ul>
  <label><input type="checkbox" v-model="simulerErreur" /> Simuler une erreur</label>
  <button :disabled="chargement" @click="charger">Recharger</button>
</template>
```

<Aside type="definition" title="Cycle de vie : onMounted">
Un composant est créé, monté dans la page, mis à jour, puis éventuellement retiré. `onMounted(fonction)` exécute la fonction **une fois lorsque cette instance est montée**. Il est fréquent de l'utiliser pour un premier chargement de données. Il ne relance pas automatiquement la requête lorsque les filtres changent.
</Aside>

### Adapter `App.vue`

**Dans `<script setup>`** de `App.vue` :

- ajouter `onMounted` à l'import venant de `vue` ;
- supprimer l'import `cafesExemples` ;
- remplacer `const cafes = ref(cafesExemples)` par le code suivant.

```js
const SOURCE = '/cafes.json' // test local stable ; l'API distante pourra être essayée ensuite

const cafes = ref([])
const chargement = ref(true)
const erreur = ref('')

async function chargerCafes() {
  chargement.value = true
  erreur.value = ''

  try {
    const reponse = await fetch(SOURCE)
    if (!reponse.ok) throw new Error(`statut HTTP ${reponse.status}`)

    const page = await reponse.json()
    if (!Array.isArray(page.items)) throw new Error('format de réponse inattendu')
    cafes.value = page.items
  } catch (e) {
    erreur.value = `Impossible de charger les cafés (${e.message}).`
  } finally {
    chargement.value = false
  }
}

onMounted(chargerCafes)
```

Dans le gabarit, **remplacer la grille actuelle** par ces éléments. La grille et ses cartes sont désormais affichées uniquement après un chargement réussi :

```html
<p v-if="chargement" class="message" role="status">Chargement des cafés…</p>
<p v-else-if="erreur" class="message erreur" role="alert">{{ erreur }}</p>
<template v-else>
  <div class="grille">
    <CarteCafe
      v-for="cafe in cafes"
      :key="cafe.slug"
      :cafe="cafe"
      :favori="favoris.includes(cafe.slug)"
      @basculer-favori="basculerFavori"
    />
  </div>
</template>
```

Ajouter les styles suivants au `<style scoped>` de `App.vue` :


**Vérification :** les cafés apparaissent avec `/cafes.json`. Dans l'onglet **Réseau** des outils de développement, observer la requête, son statut et sa réponse. Renommer temporairement l'URL en `/absent.json` pour tester le message d'erreur, puis rétablir la bonne adresse.

<Aside type="astuce" title="Ce que fait fetch">
`fetch()` renvoie une promesse. Le code attend la réponse avec `await`, vérifie `reponse.ok`, puis extrait le JSON avec `await reponse.json()`. Une réponse HTTP `404` ou `500` ne provoque pas, à elle seule, un rejet de la promesse `fetch` : **il faut vérifier le statut**. Un échec réseau peut, lui, provoquer un rejet.
</Aside>

Le composant `CarteCafe` n'a pas changé : **l'affichage dépend de la structure des données reçues, pas de leur provenance**. Si l'API réelle utilise une autre structure, il faudra adapter les données à celle attendue par les cartes.

<Aside type="definition" title="v-model">
`v-model` crée une **liaison bidirectionnelle** entre un champ et une donnée réactive : la saisie modifie la donnée, et une modification de la donnée met le champ à jour. Un champ de texte ou une liste déroulante produit généralement une chaîne ; une case à cocher simple, un booléen.
</Aside>

### Déclarer les filtres

**Dans `<script setup>`** de `App.vue`, ajouter `computed` à l'import de Vue, puis les déclarations ci-dessous :

```js
const recherche = ref('')
const ouvertsSeulement = ref(false)
const pavillon = ref('')
const carteAcceptee = ref(false)
const favorisSeulement = ref(false)

const pavillons = computed(() =>
  [...new Set(cafes.value.map((c) => c.location?.pavillon).filter(Boolean))]
    .sort((a, b) => a.localeCompare(b, 'fr')),
)

const cafesFiltres = computed(() => {
  const texte = recherche.value.trim().toLowerCase()

  return cafes.value.filter((cafe) => {
    if (ouvertsSeulement.value && !cafe.is_open) return false
    if (pavillon.value && cafe.location?.pavillon !== pavillon.value) return false
    if (carteAcceptee.value && !(cafe.payment_details ?? [])
      .some((p) => ['DEBIT', 'CREDIT'].includes(p.method))) return false
    if (favorisSeulement.value && !favoris.value.includes(cafe.slug)) return false
    const contenu = `${cafe.name ?? ''} ${cafe.description ?? ''}`.toLowerCase()
    if (texte && !contenu.includes(texte)) return false
    return true
  })
})

function reinitialiser() {
  recherche.value = ''
  ouvertsSeulement.value = false
  pavillon.value = ''
  carteAcceptee.value = false
  favorisSeulement.value = false
}
```

Le filtre « Carte acceptée » cherche explicitement les codes `DEBIT` ou `CREDIT`, plutôt que de considérer que tout moyen autre que le comptant est une carte. Le filtre de recherche porte ici sur **le nom et la description** du café, pas sur le menu.

## Vers plusieurs pages : le routage

Une suite naturelle serait d'afficher la fiche détaillée d'un café. Si on stockait simplement le café choisi dans une variable de `App.vue` pour afficher une fiche avec `v-if`, l'URL resterait inchangée : impossible de partager directement la fiche et le bouton **Précédent** ne reviendrait pas nécessairement à la liste.

<Aside type="definition" title="Routage côté client">
Le **routage côté client** associe des adresses de l'application à des composants à afficher. Dans une application monopage (SPA), le routeur peut changer le composant affiché et l'URL sans recharger un nouveau document HTML. Avec Vue, on utilise habituellement la bibliothèque officielle **Vue Router**.
</Aside>

Voici **un aperçu**, non une étape à exécuter maintenant : les composants `ListeCafes` et `FicheCafe` ainsi que l'installation du routeur seront abordés dans la page suivante.

```js
import { createRouter, createWebHistory } from 'vue-router'
import ListeCafes from './components/ListeCafes.vue'
import FicheCafe from './components/FicheCafe.vue'

export default createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', component: ListeCafes },
    { path: '/cafes/:slug', component: FicheCafe },
  ],
})
```

Le routage fera l'objet de la prochaine page : routes et paramètres, liens, navigation et gestion des adresses inconnues.

## Récapitulatif

| Concept | Syntaxe | Rôle |
| --- | --- | --- |
| Composant | fichier `.vue` avec `<script setup>`, `<template>`, `<style scoped>` | regrouper une responsabilité d'interface |
| Prop | `defineProps()`, `:prop="…"` | transmettre des informations du parent à l'enfant |
| Événement émis | `defineEmits()`, `emit('nom', valeur)`, `@nom` | signaler une interaction au parent |
| État partagé | `ref()` dans le parent commun | permettre à plusieurs composants de travailler sur une même information |
| Cycle de vie | `onMounted(…)` | effectuer une action après le montage d'un composant |
| Requête HTTP | `fetch`, `reponse.ok`, `reponse.json()` | obtenir des données, gérer le chargement et les erreurs |
| Formulaire | `v-model` | lier un champ à une donnée réactive |
| Liste calculée | `computed()` | déduire les résultats affichés des données et des filtres |
| Routage (aperçu) | `createRouter()` | associer une adresse à un composant |

- Un composant réutilisable reçoit des données, sans devoir connaître leur provenance.
- Le parent possède les données communes et reçoit les événements de ses enfants.
- Un chargement doit distinguer **en cours**, **réussi** et **échoué**.
- Les filtres calculent une nouvelle liste à afficher sans modifier les données sources.
