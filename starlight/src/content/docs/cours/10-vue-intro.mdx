Dans les applications web précédentes (avec PHP), le serveur pouvait produire 
directement les pages HTML à afficher. Avec une architecture reposant sur des **APIs**, 
le serveur fournit plutôt des données, tandis que le navigateur prend une plus 
grande part de responsabilité dans la construction et l'actualisation de l'interface.

Nous pouvons accomplir ce travail avec du JavaScript pur (*Vanilla JavaScript*), mais
ce serait un travail assez hardu. 
Dans cette page, nous découvrirons **Vue.js**, un *cadriciel* (*framework*) qui facilite 
la construction d'interfaces interactives, la gestion de leur état et leur mise à jour 
lorsque les données changent.

## Pourquoi un cadriciel côté client

Rendre une page HTML interactive avec du JavaScript pur est tout à fait possible.  
Voici une page comprenant un **compteur de mentions d'appréciation (« kudos »)** :

```html
<p>Ce projet a reçu <span id="kudos">0</span> kudo(s).</p>
<button id="btnKudo">👍</button>

<script>
  let kudos = 0;
  const affichage = document.querySelector('#kudos');

  document.querySelector('#btnKudo').addEventListener('click', () => {
    kudos++;
    affichage.textContent = kudos;   // ne pas oublier de mettre l'affichage à jour
  })
</script>
```

Le code fonctionne, mais le programme est chargé de deux opérations (responsabilités) : **modifier la donnée** 
et **actualiser les éléments du DOM qui l'affichent**.  

#### Où est le problème ?

Avec plusieurs compteurs, une liste filtrée et d'autres éléments, ces mises à jour manuelles se multiplient et
deviennent de plus en plus difficile à suivre et effectuer de manière efficace. 
Un oubli peut entraîner l'affichage d'une information périmée.

<Aside type="definition" title="Réactivité">
La **réactivité** permet à Vue de suivre les changements des données réactives et
de mettre à jour automatiquement les parties de l'interface qui en dépendent.
</Aside>

<Highlight couleur="ambre">Avec Vue, nous décrivons les (diverses) dépendances entre l'interface et les données (réactives). 
Lorsque ces données changent, Vue met automatiquement à jour les éléments de l’interface concernés.</Highlight>

Vue n'est pas le seul cadriciel de ce genre : React, Angular et bien d'autres reposent 
sur la même idée, avec des syntaxes différentes. Les concepts de cette page se transposent 
en grande partie de l'un à l'autre.

## Installation et outils

### Deux façons d'utiliser Vue

Vue peut s'utiliser de deux façons courantes, selon les besoins du projet :
(1) pour augmenter et enrichir une page existante ou (2) pour créer une application 
monopage.

**Nous verrons d'abord comment utiliser Vue par CDN** pour enrichir une page HTML existante.
Ensuite, nous introduirons la notion de composants `.vue`, qu'on retrouve dans tout projet Vite. 
Cette seconde méthode sera introduite dans ce chapitre et développée dans le suivant.

<Tabs>
<TabItem label="Augmenter une page (via CDN)">

**Quand l'utiliser :** pour rendre interactive une page HTML existante, pour ajouter un comportement coté client à une page PHP.
Elle ne nécessite aucune installation. Le code Vue s'écrit directement dans la page.

<Aside type="definition" title="CDN">
Un **CDN**, pour *Content Delivery Network* (réseau de diffusion de contenu), 
est un réseau de serveurs qui distribue des fichiers publics, comme des bibliothèques JavaScript, 
depuis un serveur proche de la personne qui les demande. `unpkg.com` diffuse ainsi tous les paquets publiés sur npm.
</Aside>

<Steps>

1. **Créer la page ou ouvrir une page existante.** Récupérer un fichier existant (`.php`, `.html`, `.cshtml`,...) ou créer un fichier.

2. **Prévoir l'élément de montage.** Dans le `body`, identifier un élément (traditionnellement `#app`, comme `<div id="app">`) qui servira de contenant pour l'application Vue.  
Dans l'élément de montage (`#app`), nous utilisons la syntaxe `{{ message }}`, appelée **interpolation**, pour afficher la valeur d'une donnée.

   ```html
   <div id="app">
     <p>{{ message }}</p>
   </div>
   ```

3. **Importer Vue et monter l'application.** À la fin du `body`, ajouter un script de type `module` qui va importer *Vue* depuis le CDN, 
créer une application et la **monter** sur `#app` : Vue prendra alors en charge tout ce que cet élément contient.

   ```html
   <script type="module">
     import { createApp, ref } from 'https://unpkg.com/vue@3.5/dist/vue.esm-browser.js'

     createApp({
       setup() {
         const message = ref('Bonjour de Vue')
         return { message }   // ce qui est retourné est utilisable dans la page
       },
     }).mount('#app')
   </script>
   ```

   La fonction `setup()` prépare les données et les fonctions de l'application. Tout ce qu'elle **retourne** devient utilisable dans le HTML monté.

4. **Ouvrir la page dans le navigateur.** Un double-clic sur `index.html` suffit : la page doit afficher « Bonjour de Vue ».  
    <Aside type='erreur' title="« Bonjour de Vue » ne s'affiche pas">
    Si `{{ message }}` reste affiché tel quel, Vue n'a pas démarré. Pour comprendre ce qui se passe, ouvre la console des outils de développement (<kbd>F12</kbd>).
    </Aside>

</Steps>

**Quand l'utiliser :** pour construire une application complète, 
découpée en composants. Le code est réparti dans des fichiers `.vue`, 
un par composant.

<Aside type="definition" title="Rôle de Vite">
Pendant le développement, **Vite** sert l'application et met la page à jour à chaque enregistrement, 
sans la recharger entièrement. Pour la mise en ligne, il **construit** l'application : 
il traduit les fichiers `.vue` en JavaScript (ordinaire), et place le tout dans un dossier `dist/`.
</Aside>

<Steps>

1. **Vérifier Node.js.** Le générateur de projet Vue exige une version compatible de Node.js (actuellement `^22.18.0 || >=24.12.0`). Si Node.js est déjà installé pour les exercices avec Express, vérifier sa version dans un terminal :

   ```bash
   node --version
   ```

2. **Créer le projet.** Dans le dossier dans lequel vous souhaitez créer le projet, exécute la commande suivante :

   ```bash
   npm create vue@latest
   ```

   L'assistant posera quelques questions, comme lorsqu'on exécute `npm init`.

3. **Installer les dépendances.** Après s'être positionné dans le dossier créé par `npm create vue@latest`, exécuter la commande suivante : `npm install`. Elle télécharge Vue, Vite et les autres paquets nécessaires dans le dossier `node_modules/` du projet.

   ```bash
   cd cafes-udem
   npm install
   ```

4. **Lancer le serveur de développement.**

   ```bash
   npm run dev
   ```

   La commande affiche une adresse, en général `http://localhost:5173`, à ouvrir dans le navigateur. Le terminal doit rester ouvert : arrêter la commande, avec <kbd>Ctrl</kbd>+<kbd>C</kbd>, arrête aussi le serveur.

5. **Repérer les fichiers du projet.** La plupart du travail se fait dans `src/`.

   ```text
   cafes-udem/
   ├── index.html              la seule page HTML : elle contient <div id="app">
   ├── package.json
   ├── vite.config.js          la configuration de Vite
   ├── public/                 fichiers copiés tels quels (images, données)
   └── src/
       ├── main.js             crée l'application et la monte sur #app
       ├── App.vue             le composant principal
       └── components/         les autres composants
   ```

   Le fichier `main.js` joue le même rôle que le script de la version CDN : il crée l'application et la monte sur `#app`.  
   La différence est que **l'application est maintenant un composant, `App.vue`**.

   ```js
   // src/main.js
   import { createApp } from 'vue'
   import App from './App.vue'

   createApp(App).mount('#app')
   ```

## Tutoriel : Portfolio interactif

Inès, étudiante en développement web, a conçu la page de son portfolio en HTML et en CSS. 
La page s'affiche bien, mais elle aimerait également :

- un bouton pour activer ou désactiver le **mode sombre** ;
- des boutons pour **filtrer** les projets par technologie ;
- des boutons **Détails** pour afficher les apprentissages associés à chaque projet ;
- une séparation entre les **données** (profil, compétences et projets) et le HTML qui les affiche.

Le dossier de départ contient les fichiers `index.html` et `style.css`. 
Nous allons progressivement enrichir cette page.  
**Tout le code du portfolio utilisera Vue par CDN** et la fonction `setup()`.

### Étape 1 : monter Vue sur la page (`createApp`)

On commence par entourer le contenu de la page d'un conteneur `#app`, puis on ajoute le script à la fin du `body`. 
> Les informations du profil sont définies dans le script, puis affichées dans le HTML par **interpolation**, avec la syntaxe `{{ }}`.  
> Le profil ne change pas au cours de cet exemple : un objet JavaScript ordinaire suffit.

```html "id="app"" "{{ profil.nom }}" "{{ profil.titre }}" "createApp" "setup()" "mount('#app')" "const profil"
<div id="app" v-cloak>
  <div class="site">
    <header class="entete conteneur">
      <!-- ... -->
      <h1>{{ profil.nom }}</h1>
      <p class="titre">{{ profil.titre }}</p>
    </header>
    <!-- ... le reste de la page -->
  </div>
</div>

<script type="module">
  import { createApp, ref, computed } from 'https://unpkg.com/vue@3.5/dist/vue.esm-browser.js'

  createApp({
    setup() {
      const profil = {
        nom: 'Inès Gagnon',
        titre: "Étudiante en techniques de l'informatique, profil développement web",
        courriel: 'ines.gagnon@exemple.test',
        disponible: true,
      }

      return { profil }
    },
  }).mount('#app')
</script>
```

> Les fonctions `ref` et `computed` seront utilisées aux étapes suivantes.

<Aside type="tip" title="Attribut v-cloak">
En **mode CDN**, avant que Vue ne soit chargé, la page affiche brièvement les `{{ }}` bruts.  
L'attribut `v-cloak`, que Vue retire au montage, permet de masquer le conteneur d'ici là, avec une règle CSS : `[v-cloak] { display: none; }`.
</Aside>

<Aside type="definition" title="Interpolation">
L'**interpolation** insère le résultat d'une expression JavaScript dans le texte HTML :  
`{{ profil.nom }}` affiche `Inès Gagnon`. Vue échappe le texte inséré. Donc, une balise présente dans la valeur ne sera pas interprétée comme du HTML, de façon comparable à `htmlspecialchars()` en PHP.
</Aside>

<Aside type="caution" title="Le conteneur lui-même n'est pas compilé">
Vue utilise le **contenu** de `#app` comme gabarit, mais pas l'élément attaché à `#app` lui-même. Une directive placée sur `<div id="app">`, 
comme `:class`, serait ignorée. D'où le second conteneur, `<div class="site">`, qui recevra la classe du thème à l'étape 3.
</Aside>

### Étape 2 : réagir aux clics et directives

Pour réagir à un événement, on utilise la directive `v-on` ou son raccourci `@`, par exemple `@click` pour un clic.

<DemoCompteur client:visible />

> Le code de cette démonstration est présenté dans un composant `.vue`. Dans le portfolio, les déclarations se placent plutôt dans la fonction `setup()` et les variables utilisées dans le HTML doivent être incluses dans le `return`. La réactivité et les directives fonctionnent de la même façon.

```vue "@click"
<script setup>
import { ref } from 'vue'

const mentions = ref(0)
</script>

<template>
  <div class="demo not-content">
    <p>Ce projet a reçu {{ mentions }} kudo(s).</p>
    <div class="ligne">
      <button @click="mentions++">👍</button>
      <button @click="mentions = 0">Réinitialiser</button>
    </div>
  </div>
</template>
```

#### La fonction `ref()`

`ref(valeur)` crée une **référence réactive**. Elle est utilisée lorsque l'information (`valeur`) 
peut changer pendant l'utilisation et que l'interface en dépend.
Elle permet à Vue de suivre les changements de la valeur et mettre à jour ce qui en dépend.

**Lorsqu'on utilise `ref`:**
- Dans le script JS, on accède à la valeur avec `.value` : `mentions.value++`.
- Dans le gabarit Vue (`<template>` ou HTML monté par Vue), la référence est automatiquement déballée : on écrit `{{ mentions }}` ou `@click="mentions++"`, sans `.value`.

#### Directives

En Vue.js, une **directive** est un attribut spécial que l'on ajoute à un élément HTML, , généralement écrit avec le préfixe `v-`.
Elle indique à Vue comment cet élément doit se comporter ou être mis à jour en fonction des données de l'application.

<Aside type="definition" title="Quand les utiliser ?">
Les directives permettent notamment de contrôler l'affichage, de réagir aux événements et de synchroniser des données avec des éléments de l'interface.
</Aside>

`@click` utilisé plus haut est en réalité le raccourci de `v-on:click` : la directive exécute une expression ou appelle une fonction en réponse à un clic.


#### Application dans le portfolio

Dans notre exemple de Portfolio, le thème devient une donnée, que le bouton inverse :

##### Dans `<script>`

```js
const sombre = ref(false)

return { profil, sombre }
```

##### Dans `#app` (HTML)

```html
<button @click="sombre = !sombre">{{ sombre ? 'Mode clair' : 'Mode sombre' }}</button>
```

Il reste encore à définir les règles de style rattachées au mode sombre.

### Étape 3 : lier des attributs (directive `v-bind`)

#### Retour sur la fonction `ref()`

Nous avons vu que la fonction `ref()` permet de créer une donnée réactive : 
lorsque sa valeur change, Vue peut détecter ce changement et actualiser les parties 
de l'interface qui en dépendent.

Cependant, **`ref()` ne détermine pas comment cette donnée doit apparaître dans le HTML.** 
C'est le rôle des expressions et des directives utilisées dans le gabarit (`<template>`).

Jusqu'à présent, nous avons utilisé l'interpolation `{{ }}` pour afficher une valeur
dans le contenu d'un élément :

```html
<p>Mode sombre : {{ sombre }}</p>
```

Mais comment utiliser cette même donnée pour modifier un attribut HTML, comme `src`, `href`, `disabled` ou `class` ?

C'est précisément le rôle de la directive **`v-bind`**.

#### La directive `v-bind`

La directive `v-bind` (ou son raccourci `:`) permet de lier un attribut HTML à une expression JavaScript. 
Lorsque les données réactives utilisées dans cette expression changent, Vue actualise automatiquement l'attribut.

**Par exemple :**

```html
<button v-bind:aria-pressed="sombre">
  Changer de thème
</button>
```

**ou (son équivalent):**

```html
<button :aria-pressed="sombre">
  Changer de thème
</button>
```

L'attribut `aria-pressed` reçoit la valeur de `sombre` et est actualisé lorsque cette valeur change.

##### Le cas particulier de `class`

Pour `class`, Vue accepte un objet : chaque classe est appliquée si sa valeur est vraie.
Nous pouvons utiliser `:class` pour déterminer dynamiquement les classes d'un élément.

**Par exemple :**
```html
<div class="site" :class="sombre ? 'sombre' : ''">
```

Cette expression ajoute la classe sombre uniquement lorsque la variable sombre vaut `true`.

Cependant, puisque cette opération est très fréquente, Vue propose une syntaxe particulière pour `class` : un objet JavaScript dont les propriétés représentent des classes CSS.

```html
<div class="site" :class="{ sombre: sombre }">
```

Décomposons cette expression :

- `{ }` délimite un objet JavaScript.
- Le premier `sombre` correspond au nom de la classe CSS.
- Le second `sombre` correspond à la variable JavaScript qui détermine si cette classe doit être appliquée.

Pour chaque propriété de l'objet, Vue examine la valeur associée : si elle est vraie (truthy), la classe est ajoutée; sinon, elle est retirée.

- Si `sombre` est `false` : `class="site"`
- Si `sombre` est `true` : `class="site sombre"`

<Aside type='tip' title='class et :class se combinent'>
L'attribut `class` ordinaire et la directive `:class` se combinent. 
La classe `site` est permanente, tandis que la classe `sombre` dépend de la donnée réactive.
</Aside>

Il est également possible de gérer plusieurs classes indépendamment :

```html
<div :class="{ sombre: sombre, actif: estActif, erreur: aErreur }">
```

Chaque classe est ajoutée ou retirée selon la valeur de l'expression correspondante.

#### Exemple : changer le thème d'une page

<DemoLiaison client:visible />

```vue ":class" ":aria-pressed"
<script setup>
import { ref } from 'vue'

const sombre = ref(false)
</script>

<template>
  <div class="demo" :class="{ sombre: sombre }">
    <p>Thème actuel : {{ sombre ? 'sombre' : 'clair' }}</p>
    <button @click="sombre = !sombre" :aria-pressed="sombre">
      Changer de thème
    </button>
  </div>
</template>
```

#### Application au portfolio

Dans le portfolio, la feuille de style prévoit déjà une classe `sombre`. 
Il suffit de la lier à la donnée :

```html
<div class="site" :class="{ sombre: sombre }">
```

L'élément conserve sa classe `site`, tandis que la présence de sombre dépend de la variable réactive.

### Étape 4 : afficher des listes (directive `v-for`)

La directive `v-for` répète un élément pour chaque valeur d'un tableau.  
Lorsqu'on l'utilise, l'attribut `:key` donne à chaque répétition un identifiant unique, 
qui permet à Vue de savoir quel élément a été ajouté, retiré ou déplacé.

<DemoListe client:visible />

```vue "v-for" ":key"
<script setup>
import { ref } from 'vue'

const competences = ref([
  { id: 1, nom: 'HTML' },
  { id: 2, nom: 'CSS' },
  { id: 3, nom: 'JavaScript' },
])
const suggestions = ['PHP', 'MySQL', 'Git', 'Vue.js']
let prochainId = 4

function ajouter() {
  const nom = suggestions[(prochainId - 4) % suggestions.length]
  competences.value.push({ id: prochainId++, nom })
}

function retirer(id) {
  competences.value = competences.value.filter((c) => c.id !== id)
}
</script>

<template>
  <div class="demo">
    <ul>
      <li v-for="competence in competences" :key="competence.id">
        {{ competence.nom }}
        <button @click="retirer(competence.id)" aria-label="Retirer">×</button>
      </li>
    </ul>
    <p v-if="competences.length === 0" class="note">Aucune compétence pour l'instant.</p>
    <button @click="ajouter">Ajouter une compétence</button>
  </div>
</template>
```

C'est le même travail de *refactoring* que l'extraction des données que nous avions fait sur les [pages dynamiques](/cours/03-page-dynamique) : 
- En PHP, une boucle `foreach` produisait les cartes à partir d'un tableau \
- Ici, `v-for` le fait dans le navigateur. Dans le portfolio, les compétences et les projets passent dans le script :

```js
const competences = ['HTML', 'CSS', 'JavaScript', 'PHP', 'MySQL', 'Express', 'Vue', 'Git']

const projets = [
  { id: 1, titre: 'Recettes de grand-maman', technos: ['HTML', 'CSS'],
    description: "Site vitrine de recettes familiales, adapté à toutes les tailles d'écran.",
    appris: 'les grilles CSS et les requêtes média.' },
  // … les cinq autres projets, avec chacun un id distinct
]
```

Les six blocs `<article>` écrits à la main se réduisent à un seul, répété :

```html "v-for" ":key"
<article v-for="projet in projets" :key="projet.id" class="projet">
  <h3>{{ projet.titre }}</h3>
  <p>{{ projet.description }}</p>
  <div class="technos">
    <span v-for="techno in projet.technos" :key="techno">{{ techno }}</span>
  </div>
  <p class="appris">Ce que j'ai appris : {{ projet.appris }}</p>
  <button>Détails</button>
</article>
```

<MarginNote type="rappel" titre="Une clé unique et stable">
La clé doit être unique parmi les éléments répétés et rester attachée au même élément. Un champ `id` est préférable au titre, qui pourrait être modifié ou dupliqué. La position dans le tableau est également une mauvaise clé lorsque la liste peut être filtrée ou réordonnée.
</MarginNote>

### Étape 5 : filtrer avec une propriété calculée

<Aside type="definition" title="Donnée ordinaire, état réactif ou valeur calculée ?">
- **Donnée ordinaire** : une information fixe pendant l'utilisation de la page, comme le profil ou la liste initiale des projets.
- **État réactif** (`ref`) : une information qui peut changer pendant l'utilisation et dont l'interface dépend, comme le mode sombre ou le filtre sélectionné.
- **Valeur calculée** (`computed`) : une information déduite d'autres données réactives, comme la liste des projets correspondant au filtre choisi. Nous l'utiliserons à l'étape 5.
</Aside>

Le filtre retenu est une donnée, `filtre`. La liste affichée, elle, se **déduit** de cette donnée et des projets : c'est le rôle d'une propriété calculée.

<DemoComputed client:visible />

```vue {14-20} "computed"
<script setup>
import { ref, computed } from 'vue'

const projets = [
  { id: 1, titre: 'Site de recettes', technos: ['HTML', 'CSS'] },
  { id: 2, titre: 'Quiz interactif', technos: ['HTML', 'JavaScript'] },
  { id: 3, titre: 'Catalogue en ligne', technos: ['PHP', 'MySQL'] },
  { id: 4, titre: 'Météo en direct', technos: ['JavaScript', 'Vue'] },
]
const technos = ['Toutes', 'HTML', 'CSS', 'JavaScript', 'PHP', 'MySQL', 'Vue']

const filtre = ref('Toutes')

const projetsFiltres = computed(() => {
  if (filtre.value === 'Toutes') {
    return projets
  }

  return projets.filter((p) => p.technos.includes(filtre.value))
})
</script>

<template>
  <div class="demo">
    <div class="ligne">
      <button
        v-for="techno in technos"
        :key="techno"
        :class="{ actif: techno === filtre }"
        @click="filtre = techno"
      >
        {{ techno }}
      </button>
    </div>
    <p class="note">{{ projetsFiltres.length }} projet(s)</p>
    <ul>
      <li v-for="projet in projetsFiltres" :key="projet.id">
        {{ projet.titre }} ({{ projet.technos.join(', ') }})
      </li>
    </ul>
  </div>
</template>
```

<Aside type="definition" title="Propriété calculée (`computed`)">
`computed(() => …)` définit une valeur dérivée. Vue suit les **dépendances réactives** utilisées dans son calcul et conserve le résultat en mémoire tant qu'elles ne changent pas. Comme avec `ref`, on accède au résultat par `.value` dans le script et directement dans le gabarit.

Dans notre exemple, `filtre` est réactif, mais `projets` est un tableau ordinaire : le calcul réagit au changement de filtre, **pas** à une modification ultérieure du tableau `projets`. Si des projets pouvaient être ajoutés, retirés ou chargés depuis une API au cours de l'utilisation, on pourrait aussi les déclarer avec `ref([])`.
</Aside>

#### Application au portfolio

Pour le portfolio, les boutons de filtre sont eux aussi produits à partir des données : la liste des technologies se déduit des projets, sans doublon.

```js
const filtre = ref('Toutes')

// Les technologies des projets, sans doublon, précédées de « Toutes »
const technos = ['Toutes', ...new Set(projets.flatMap((p) => p.technos))]

const projetsFiltres = computed(() => {
  if (filtre.value === 'Toutes') {
    return projets
  }

  return projets.filter((p) => p.technos.includes(filtre.value))
})
```

```html
<div class="filtres">
  <button
    v-for="techno in technos"
    :key="techno"
    :class="{ actif: techno === filtre }"
    @click="filtre = techno"
  >{{ techno }}</button>
</div>

<article v-for="projet in projetsFiltres" :key="projet.id" class="projet">
```

<Checkpoint question="Pourquoi ne pas filtrer directement le tableau projets, avec projets = projets.filter(…), au clic sur un bouton ?">
Parce que les projets écartés seraient perdus : revenir à « Toutes », ou passer d'une technologie à une autre, n'aurait plus rien à afficher. La propriété calculée laisse intactes les données d'origine, et en déduit à chaque changement la liste à afficher.
</Checkpoint>

### Étape 6 : afficher sous condition (directive `v-if`, `v-show`)

Deux directives affichent un élément sous condition, de deux façons différentes.

<DemoConditions client:visible />

```vue "v-if" "v-else" "v-show"
<script setup>
import { ref } from 'vue'

const disponible = ref(true)
const details = ref(false)
</script>

<template>
  <div class="demo">
    <p v-if="disponible" class="oui">Disponible pour un stage cet été</p>
    <p v-else class="non">Stage déjà trouvé, merci !</p>

    <p v-show="details" class="note">Stage de huit semaines, à partir de mai, en développement web.</p>

    <div class="ligne">
      <button @click="disponible = !disponible">Changer la disponibilité</button>
      <button @click="details = !details">{{ details ? 'Masquer' : 'Afficher' }} les détails</button>
    </div>
  </div>
</template>
```

- La directive `v-if` crée ou retire réellement l'élément de la page. Elle se combine avec `v-else-if` et `v-else`.
- La directive `v-show` laisse l'élément dans la page, et le masque avec `display: none`.

> Dans l'inspecteur du navigateur, le paragraphe de `v-if` disparaît du HTML, tandis que celui de `v-show` y reste, masqué. 

- `v-if` est recommandé lorsque l'élément à afficher dépend d'une condition qui change rarement, ou lorsque l'élément ne doit pas exister du tout.
- `v-show` est recommandé lorsque l'élément est affiché et masqué souvent 

#### Application au portfolio

Dans le portfolio, le bandeau de disponibilité dépend du profil et les détails de chaque projet s'affichent à la demande. 
Pour ouvrir chaque panneau indépendamment, nous conservons les **identifiants** des projets ouverts dans une référence réactive :

##### Dans `<script>`

```js
const ouverts = ref([])   // identifiants des projets dont les détails sont affichés

function basculerDetails(id) {
  if (ouverts.value.includes(id)) {
    ouverts.value = ouverts.value.filter((projetId) => projetId !== id)
  } else {
    ouverts.value.push(id)
  }
}
```

##### Dans `#app`(HTML)

```html "v-if" "v-show"
<span v-if="profil.disponible" class="dispo">Disponible pour un stage à l'été 2027</span>

<p v-show="ouverts.includes(projet.id)" class="appris">Ce que j'ai appris : {{ projet.appris }}</p>
<button @click="basculerDetails(projet.id)" :aria-expanded="ouverts.includes(projet.id)">
  {{ ouverts.includes(projet.id) ? 'Masquer' : 'Détails' }}
</button>
```

Sans oublier d'ajouter au `return` tout ce que le HTML utilise : `return { profil, competences, sombre, filtre, technos, projetsFiltres, ouverts, basculerDetails }`.

## Découvrir les composants `.vue`

Jusqu'ici, le portfolio utilisait une page HTML et un script chargé par CDN. Pour les applications plus importantes, nous pouvons répartir l'interface en **composants réutilisables** dans des fichiers `.vue`, grâce à un projet Vite.

<Aside type="definition" title="Composant et SFC">
Un **composant** regroupe une partie de l'interface, son comportement et éventuellement ses styles. Un fichier `.vue` est un *Single-File Component* (**SFC**, composant monofichier) : il rassemble ces éléments dans un seul fichier, traité par l'outil de compilation.
</Aside>

Voici un composant simple :

```vue
<script setup>
import { ref } from 'vue'

const message = ref('Bonjour de Vue')
</script>

<template>
  <p>{{ message }}</p>
</template>

<style scoped>
p { font-weight: 600; }
</style>
```

### `<script setup>` — L'état et le comportement

Cette section contient le code JavaScript du composant : imports, données, état réactif, calculs et fonctions utilisées par l'interface. 
Les déclarations faites au niveau principal sont directement accessibles dans le gabarit, sans `return` explicite.

```vue
<script setup>
import { ref } from 'vue'

const message = ref('Bonjour de Vue')
</script>
```

### `<template>` — La structure (gabarit)

Cette section contient le HTML enrichi par la syntaxe de Vue. 
On y utilise les valeurs et fonctions déclarées dans `<script setup>` :

```vue
<template>
  <p>{{ message }}</p>
</template>
```

### `<style scoped>` — L'apparence

Cette section optionnelle définit des règles CSS. Avec `scoped`, Vue limite principalement la portée des sélecteurs aux éléments du composant, plutôt qu'à l'ensemble de l'application.

```vue
<style scoped>
p { font-weight: 600; }
</style>
```

Les styles globaux peuvent toujours affecter le composant. Les règles de la **cascade CSS** (spécificité, ordre, etc.) continuent de déterminer quels styles s'appliquent : `scoped` ne garantit pas la priorité des règles locales sur toutes les règles globales.

### Deux syntaxes pour les mêmes concepts

| Portfolio par CDN (`setup()`) | Fichier `.vue` (`<script setup>`) |
| --- | --- |
| On appelle `createApp({ setup() { … } })` dans un script de la page HTML. | On écrit les déclarations dans la section `<script setup>` du composant. |
| `setup()` retourne les variables et fonctions à rendre accessibles au HTML. | Les déclarations principales sont accessibles dans `<template>` sans `return`. |
| Les directives s'écrivent dans le HTML à l'intérieur de `#app`. | Les directives s'écrivent dans `<template>`. |
| Le navigateur charge directement Vue par CDN. | Vite compile les fichiers `.vue` et sert l'application. |

Les mécanismes `ref`, `computed`, `v-bind`, `v-for`, `v-if` et `@click` restent les mêmes. **On ne place pas un bloc `<script setup>` directement dans une page HTML chargée par CDN** : cette syntaxe doit être compilée comme partie d'un fichier `.vue`.

## Et ensuite

Dans le prochain cours et pour la suite, nous utiliserons un projet Vite pour construire une interface organisée en composants et consommer des données provenant d'une API.

## Récapitulatif

| Concept | Syntaxe | Rôle |
| --- | --- | --- |
| Interpolation | `{{ expression }}` | afficher une valeur dans le texte, échappée |
| Donnée réactive | `ref(valeur)`, `.value` dans le script | une valeur dont les changements mettent la page à jour |
| Événement | `@click="…"` (`v-on`) | réagir à une action de la personne |
| Liaison d'attribut | `:class="…"` (`v-bind`) | donner à un attribut la valeur d'une expression |
| Liste | `v-for="x in liste"` avec `:key` | répéter un élément pour chaque valeur |
| Propriété calculée | `computed(() => …)` | déduire une valeur d'autres données, sans la recalculer inutilement |
| Condition | `v-if`, `v-else-if`, `v-else`, `v-show` | afficher un élément sous condition |
| Montage par CDN | `createApp({ setup() { … return … } }).mount('#app')` | rendre interactive une page existante ; seul le contenu de `#app` sert de gabarit |
| Composant monofichier | `<script setup>`, `<template>`, `<style scoped>` | organiser une interface en composants `.vue`, compilés avec Vite |
