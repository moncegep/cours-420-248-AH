Plutôt que de recopier les (mêmes) instructions de connexion à la base de données dans chaque page,
il est préférable de les écrire une fois, dans un fichier distinct, puis de l'importer au besoin 
dans les pages communicant avec la base de données.

<Aside type='tip' title='Principe de programmation: DRY'>
Le principe *Don’t repeat yourself* (DRY, en français : Ne vous répétez pas)
consiste à éviter la redondance de code au sein d’une application afin de faciliter la maintenance, le test, le débogage et les évolutions de celle-ci.  
Dans notre cas, recopier la connexion dans chaque page reviendrait à devoir modifier cinq fichiers le jour où le mot de passe change. 
</Aside>

#### Fichier de connexion `includes/db.php`

```php
<?php

/**
 * Ouvre la connexion à la base de données et définit la variable $pdo pour la 
 * page appelante.
 */

const BD_HOTE         = 'localhost';
const BD_NOM          = 'erabliere';
const BD_UTILISATEUR  = 'root';
const BD_MOT_DE_PASSE = '';

// Identification de la base de données
$dsn = 'mysql:host=' . BD_HOTE . ';dbname=' . BD_NOM . ';charset=utf8mb4';

// Options utilisées par PDO lors de la communication avec la base de données
$options = [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
    PDO::ATTR_EMULATE_PREPARES   => false,
];

// Tentative de connexion à la base de données
try {
    $pdo = new PDO($dsn, BD_UTILISATEUR, BD_MOT_DE_PASSE, $options);
} catch (PDOException $e) {
    http_response_code(500); // indique au client (navigateur) que le serveur a rencontré une condition inattendue
    exit('Connexion à la base de données impossible.');
}
```

#### À quoi servent les options ?

- `ERRMODE_EXCEPTION` demande à PDO de lever une exception lorsqu'une opération échoue. Elle est le comportement par défaut depuis PHP 8.
- `DEFAULT_FETCH_MODE` évite de répéter `PDO::FETCH_ASSOC` à chaque lecture. Les lignes arrivent sous forme de tableaux associatifs, avec les noms de colonnes comme clés.
- `EMULATE_PREPARES` à `false` demande que les requêtes préparées soient réellement préparées par le serveur, plutôt que reconstituées par PDO avant l'envoi.

<Aside type="caution" title="Le message d'erreur en dit long">
`$e->getMessage()` contient souvent le nom de la BD, celui de l'utilisateur et le détail de l'échec. 

Durant le développement, l'afficher fait gagner du temps. Cependant, sur un site en ligne, 
c'est de l'information en trop pour l'utilisateur et qui présente certains risques si l'utilisateur est mal intentionné.

**La bonne pratique est de journaliser (écrire en *log*) le détail de l'erreur et afficher un message plus neutre à l'utilisateur.**
</Aside>

<MarginNote type="astuce" titre="Portée de $pdo">
`require_once` insère le fichier dans la portée de l'endroit où il est appelé. Appelé au premier niveau d'une page, `$pdo` devient une variable ordinaire de cette page. Appelé à l'intérieur d'une fonction, il n'existerait que dans cette fonction.
</MarginNote>

<Aside type="prerequis" title="Créer la base de données">
Assurez-vous que la base de données `erabliere` existe dans votre instance MySQL,
en vous rendant dans la page *phpMyAdmin*.
</Aside>

Nous allons créer la table `produits` et la peupler de quelques données pour faciliter le développement de nos pages CRUD.

La structure de la table et les données de départ tiennent dans un fichier SQL, exécuté une fois depuis *phpMyAdmin*. 

```sql
-- init.sql
-- Structure et données de départ. À exécuter dans la BD erabliere.

DROP TABLE IF EXISTS produits;

CREATE TABLE produits (
    id        INT AUTO_INCREMENT PRIMARY KEY,
    nom       VARCHAR(100)  NOT NULL,
    categorie VARCHAR(40)   NOT NULL,
    prix      DECIMAL(6, 2) NOT NULL,
    stock     INT           NOT NULL DEFAULT 0,
    cree_le   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4;

INSERT INTO produits (nom, categorie, prix, stock) VALUES
    ('Sirop d''érable doré 540 ml',  'sirop',      14.50, 12),
    ('Sirop d''érable ambré 540 ml', 'sirop',      15.25,  7),
    ('Beurre d''érable 250 g',       'tartinade',   9.95,  0),
    ('Gelée d''érable 190 ml',       'tartinade',  11.00,  9),
    ('Tire sur la neige',            'confiserie',  6.25, 30),
    ('Coffret découverte',           'coffret',    39.00,  5);
```

#### Grandes étapes

<Steps>

1. Démarrez Apache et MySQL dans le panneau XAMPP.
2. Ouvrez `http://localhost/phpmyadmin`, puis créez la base de données `erabliere` si elle n'existe pas, avec l'interclassement `utf8mb4_general_ci`.
3. Sélectionnez la base de données, ouvrez l'onglet « SQL », collez le contenu de `init.sql` et exécutez.
4. Vérifiez dans l'onglet « Parcourir » que les six produits apparaissent, avec leur date de création.

</Steps>

<MarginNote type='astuce' titre='Équivalent en ligne de commande'>
En ligne de commande, la même chose s'écrit d'une traite.

```bash
mysql -u root erabliere < init.sql
```
</MarginNote>


<Aside type="caution" title="Où placer le fichier init.sql ?">
Un fichier `.sql` d'initialisation ne devrait pas être exécuté par le serveur web.  
Si nous le plaçons directement dans le dossier du site, il restera lisible par quiconque connaît son adresse. 

On le place à côté du projet plutôt qu'à l'intérieur de la racine publique.
</Aside>

**CRUD** est l'acronyme des quatre opérations de base sur des données persistantes : 

- *create* (créer) : Ajouter une ou plusieurs nouvelles données. Utilise l'opération `INSERT`.
- *read* (lire) : Récupérer des données complètes, agrégées ou filtrées. Utilise l'opération `SELECT`.
- *update* (modifier) : Modifier une ou plusieurs données existantes. Utilise l'opération `UPDATE`.
- *delete* (supprimer) : Supprimer une ou plusieurs données existantes. Utilise l'opération `DELETE`.

```php
<?php

/**
 * Contrôle les champs d'un produit.
 * Retourne deux tableaux : les erreurs par champ, et les valeurs converties.
 */
function validerProduit(array $donnees, array $categories): array
{
    $erreurs = [];
    $valeurs = [];

    $valeurs['nom'] = trim($donnees['nom'] ?? '');
    if ($valeurs['nom'] === '') {
        $erreurs['nom'] = 'Le nom est obligatoire.';
    } elseif (mb_strlen($valeurs['nom']) > 100) {
        $erreurs['nom'] = 'Le nom ne devrait pas dépasser 100 caractères.';
    }

    $valeurs['categorie'] = trim($donnees['categorie'] ?? '');
    if (!array_key_exists($valeurs['categorie'], $categories)) {
        $erreurs['categorie'] = 'Choisissez une catégorie de la liste.';
    }

    $prix = filter_var(trim($donnees['prix'] ?? ''), FILTER_VALIDATE_FLOAT);
    if ($prix === false || $prix < 0) {
        $erreurs['prix'] = 'Le prix doit être un nombre positif.';
    }
    $valeurs['prix'] = $prix === false ? 0.0 : $prix;

    $stock = filter_var(trim($donnees['stock'] ?? ''), FILTER_VALIDATE_INT);
    if ($stock === false || $stock < 0) {
        $erreurs['stock'] = 'Le stock doit être un entier positif ou nul.';
    }
    $valeurs['stock'] = $stock === false ? 0 : $stock;

    return [$erreurs, $valeurs];
}

/**
 * Valeur à réafficher dans un champ : celle qui vient d'être soumise,
 * ou à défaut celle fournie en second argument.
 */
function valeurSoumise(string $champ, string $defaut = ''): string
{
    return htmlspecialchars(trim($_POST[$champ] ?? $defaut));
}

/**
 * Affiche le message d'erreur d'un champ, s'il y en a un.
 */
function messageErreur(array $erreurs, string $champ): void
{
    if (isset($erreurs[$champ])) {
        echo '<p class="erreur">' . htmlspecialchars($erreurs[$champ]) . '</p>';
    }
}
```

<Aside type="definition" title="Le champ caché « action »">
Cette page traite deux types d'envoi (soumission) : création et suppression.  
Un champ caché (`hidden`) nommé `action` porte l'intention de la requête : `creer` ou `supprimer`. 
Le script lit ce champ afin de choisir comment traiter la requête. 
Sans cette indication explicite, il faudrait deviner à partir des champs présents, ce qui devient rapidement fragile.
</Aside>

<Aside type="tip" title="Pourquoi utilise-t-on require_once ici ?">
Le script `validation.php` (chargé dans la page) déclare des fonctions. 
Le charger deux fois provoquerait une erreur de redéclaration, d'où la variante `_once`. 
Pour le script `categories.php`, qui retourne simplement une valeur, `require` suffit. 
Il n'y a aucune conséquence à charger plusieurs fois une valeur.
</Aside>

<Aside type="tip" title="Pourquoi utilise-t-on un formulaire plutôt qu'un lien pour la suppression ?">
Utiliser un lien comme `<a href="supprimer.php?id=7">Supprimer</a>` serait plus court, et fonctionnerait à l'essai. 
Cependant, un lien annonce une ressource à consulter, et plusieurs mécanismes comme le préchargement dont disposent 
certains navigateurs ou les robots d'indexation le suivent sans que personne n'ait cliqué. Aucun de ces mécanismes 
ne s'attend à détruire quoi que ce soit. Utiliser un formulaire protège de ce genre de comportements inattendus.
</Aside>


<Aside type="tip" title="Le message après la redirection">
La redirection règle le problème du doublon, mais fait perdre tout ce que le script avait en mémoire, 
y compris le message de confirmation. La session sert précisément à palier cela : on y dépose le message 
avant de rediriger. La page suivante lit la variable de session puis l'efface.

```php
// Avant la redirection
$_SESSION['message'] = 'Produit ajouté.';
header('Location: produits.php', true, 303);
exit;
```

```php
// Au chargement de la page d'arrivée
$message = $_SESSION['message'] ?? null;
unset($_SESSION['message']);
```
</Aside>

<Checkpoint question="La suppression passe par POST et se termine par une redirection. La redirection est-elle encore utile, puisqu'un second DELETE ne supprimerait rien de plus ?">
Elle reste utile, pour une autre raison que le doublon. Sans elle, la page affichée est la réponse à un POST : la rafraîchir fait réapparaître la demande de confirmation du navigateur, et revenir dessus par l'historique renvoie le même envoi. La redirection ramène l'utilisateur sur une page consultable en GET, dont le rafraîchissement n'est qu'une relecture.
</Checkpoint>

- Un formulaire de création vide affiche toutes les erreurs d'un coup, et conserve les valeurs correctes.
- Après un ajout réussi, l'adresse est `produits.php` et le rafraîchissement n'ajoute rien.
- Le message de confirmation apparaît une fois, puis disparaît.
- `produit-modifier.php?id=9999` affiche une page « introuvable » et non une erreur PHP.
- `produit-modifier.php?id=abc` est refusé avant toute requête vers la base de données.
- Un nom contenant `<b>gras</b>` s'affiche tel quel dans la liste.
- Aucune requête n'assemble de valeur par concaténation dans la chaîne SQL.
